# Microservices Backend на Go

Учебный проект, выполненный в рамках курса по разработке микросервисов на Go.

Проект представляет собой распределённую backend-систему из нескольких взаимодействующих сервисов и предназначен для практического изучения микросервисной архитектуры, синхронного и асинхронного межсервисного взаимодействия, работы с различными хранилищами данных, API-контрактами, тестированием и observability.

## Архитектура

Проект состоит из нескольких независимо запускаемых сервисов:

- **IAM** - аутентификация и работа с пользователями
- **Inventory** - управление запасами и комплектующими
- **Order** - создание и обработка заказов
- **Payment** - обработка платежей
- **Assembly** - обработка операций сборки
- **Notification** - обработка уведомлений

Общие компоненты вынесены в отдельные модули:

- `platform` - общие инфраструктурные компоненты
- `shared` - контракты, protobuf-схемы и сгенерированный код.

Каждый сервис имеет собственный Go-модуль. Модули объединены через `go.work`.

## Межсервисное взаимодействие

Для коммуникации между сервисами используются gRPC и Apache Kafka, HTTP API используется для клиентского взаимодействия.

### gRPC

Для синхронного межсервисного взаимодействия используется gRPC.

Контракты описываются с помощью Protocol Buffers и находятся в `shared/proto`.

Go-код генерируется с использованием Buf, `protoc-gen-go` и `protoc-gen-go-grpc`.

### Apache Kafka

Для асинхронного взаимодействия используется Apache Kafka.

В проекте реализованы абстракции producer и consumer, вынесенные в общий `platform`-слой.

Kafka используется для передачи событий между сервисами. Например:

- `Order` публикует события, связанные с изменением состояния заказа
- `Order` обрабатывает события от других сервисов, например завершение сборки

События описываются через Protobuf.

## HTTP API

HTTP API сервиса `Order` описывается через OpenAPI.

HTTP API реализовано с использованием `chi`.

В приложении используются middleware для:

- аутентификации
- логирования
- recovery
- timeout
- distributed tracing

Также реализованы health/readiness endpoints.

## Работа с данными

В проекте используются несколько типов хранилищ.

### PostgreSQL

PostgreSQL используется сервисами, которым необходима реляционная модель данных.

Для работы с PostgreSQL используются:

- `pgx`
- SQL
- Squirrel
- Goose

В `Order` реализован отдельный transaction manager для выполнения бизнес-операций в рамках PostgreSQL-транзакций.

### MongoDB

Сервис `Inventory` использует MongoDB для хранения данных об инвентаре.

Для интеграционного тестирования MongoDB поднимается в контейнере с помощью Testcontainers.

### Redis

Redis используется сервисом IAM в компонентах, связанных с аутентификацией и сессиями.

## Архитектура сервисов

Сервисы разделены на отдельные слои ответственности.

В приложениях используются:

- транспортный слой для первичной обработки входящих запросов и событий
- сервисный слой для бизнес-логики
- репозиторный слой для доступа к данным
- менеджер транзакций
- отдельные gRPC клиенты
- абстракции Kafka producer и consumer
- middleware и interceptors
- общие инфраструктурные компоненты

Общая инфраструктурная логика вынесена в `platform`, чтобы не дублировать её между сервисами.

## Observability

Для наблюдаемости распределённой системы используются следующие компоненты:

### Tracing

**OpenTelemetry → Jaeger**

Jaeger используется для анализа распределенных трейсов и отслеживания прохождения запросов между сервисами.

### Logging

**OpenTelemetry → Elasticsearch → Kibana**

Логи сервисов собираются с помощью OpenTelemetry и передаются в Elasticsearch для последующего анализа в Kibana.

### Metrics

**OpenTelemetry → Prometheus → Grafana**

Метрики сервисов собираются с помощью OpenTelemetry и передаются в Prometheus для хранения и последующей визуализации в Grafana.

## Локальный запуск

### Требования

- Go 1.26+
- Docker
- Docker Compose
- [Taskfile CLI](https://taskfile.dev/docs/reference/cli)

Для того, чтобы вызывать команды из Taskfile, необходимо установить Taskfile CLI:

```
brew install go-task
```

### Генерация кода

```
task gen
```

Команда генерирует protobuf- и OpenAPI-код.

### Запуск инфраструктуры

```
task up-core
```

Команда запускает основную инфраструктуру проекта, включая необходимые компоненты Kafka и observability stack.

### Тесты

```
task test
```

### Coverage

```
task test-coverage
```

### Линтинг

```
task lint
```
